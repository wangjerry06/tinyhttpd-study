# 01 · Tinyhttpd 源码阅读路线

> 原文不到 500 行（含注释），核心文件只有两个：`httpd.c`（服务器）和 `simpleclient.c`（测试客户端）。

## 阅读顺序（按函数调用链）

```
main()                     # 入口：解析端口、初始化
  └─ startup()             # 建 socket、bind、listen —— 对照 tcp-echo-lab 复习
       └─ accept_request() # 每来一个连接就 fork 一个子进程处理
            ├─ get_line()          # 从 socket 里一行行读 HTTP 报文
            ├─ parse 以及行解析     # 拆出方法(GET/POST) 和 URL
            ├─ serve_file()        # GET：读文件发回去
            ├─ execute_cgi()       # 动态请求：fork + exec 跑 CGI 脚本
            │    ├─ 环境变量：REQUEST_METHOD / QUERY_STRING ...
            │    └─ 两条管道：cgi_input / cgi_output —— 重点难点！
            └─ not_found() / cannot_execute() / headers() 等辅助
```

## 每个函数要回答自己的问题

| 函数 | 核心问题 |
|------|----------|
| `startup` | 为什么 bind 前要 `SO_REUSEADDR`？端口占用怎么办？ |
| `accept_request` | 为什么要 fork 子进程？父进程在干嘛（`sigaction` 忽略 SIGPIPE）？ |
| `get_line` | 怎么处理 `\r\n`？一次只读一个字符的代价是什么？ |
| `execute_cgi` | 两根管道的方向？为什么 CGI 里要 `dup2` 到标准输入输出？ |

## 动手验证清单

1. `make && ./httpd 8080` 起服务，浏览器开 `http://localhost:8080/htdocs/index.html`
2. 点页面里的 color.cgi，观察 CGI 执行 → 配合 gdb 或 printf 跟踪 fork 流程
3. `curl -v http://localhost:8080/xxx` 看一个 404 的完整响应长什么样
4. 用 `htop`/`ps` 观察每个请求 fork 出的子进程
